<h2>一、先量三个数，再谈选择</h2>
<p>口径不统一，讨论就会变成各说各话。先把三个数用同一套方法量出来，后面才有比较的基础。</p>
<h3>账号周期怎么估</h3>
<p>不看「打算用多久」，看「过去同类账号实际存活多久」。取最近三批账号的中位数，再上浮 30%，作为规划值。乐观估计是选型失误的主要来源。</p>
<h3>并发怎么数</h3>
<p>数的是同时等待响应的请求，不是人数。一个人开三个标签就是三路。用代理侧的连接数曲线取 95 分位，比拍脑袋准。</p>
<h3>预算按什么口径摊</h3>
<p>建议按「每个活跃账号每月」摊，而不是按线路摊。按线路摊会掩盖闲置，按账号摊才能看出哪条线路该砍。</p>

<h2>二、周期维度：三个月和一年不是同一道题</h2>
<p>周期决定你能承受多少次地址变更。变更本身不是问题，变更多了以后账号要重新适应，才是问题。</p>
<h3>短期：可更换优先</h3>
<p>三个月以内，优先选能按天或按月灵活起停的方案，不必追求地址永久固定。这个阶段的核心是快速验证，锁定长期资源反而增加试错成本。</p>
<h3>长期：固定优先</h3>
<p>半年以上，固定出口的价值开始超过价格差异。地址稳定意味着环境稳定，环境稳定意味着少一次排查，这笔账在第六个月之后才明显。</p>

<h2>三、并发维度：一个人和十个人差在哪</h2>
<p>并发上去以后，问题从「快不快」变成「稳不稳」。这两件事对应的选型逻辑完全不同。</p>
<h3>单会话与多会话对出口的要求</h3>
<p>单会话只看延迟和可用率，一条线路足够。多会话要看线路的并发上限和连接复用能力，共享线路在这个维度上最先暴露短板。</p>
<h3>出口数量与账号数量的关系</h3>
<p>常见做法是每 3 至 5 个账号一条出口，重要账号单独一条。比例不是固定的，取决于账号之间是否需要彼此独立；需要独立的，就别省这一条。</p>

<h2>四、成本维度：摊到每个账号再看</h2>
<p>单价高低不能直接比，因为包含的东西不一样。有的含固定地址，有的含独立带宽，有的只是共享池里的一个入口。</p>
<h3>三种常见口径</h3>
<p>按线路计费、按流量计费、按并发数计费。对话场景流量小、并发中等，按线路计费通常最可控；批处理场景流量大，按流量计费可能更省。</p>
<h3>别忘了替换成本</h3>
<p>一次故障替换，包含排查、重配、验证，通常要 40 至 90 分钟。按月折算，这部分往往比线路费本身更贵，选型时应该算进去。</p>

<h2>五、五问清单，按顺序回答</h2>
<p>五个问题按顺序答，任何一个答「否」，后面的就不用问了，直接落到对应方案。</p>
<h3>问题一到三</h3>
<p>一、这个账号会不会用超过半年？二、是否要求出口地址在周期内完全不变化？三、峰值并发是否超过 8 路？前两个「是」偏静态，第三个「是」意味着需要多条出口而不是一条更强的出口。</p>
<h3>问题四到五</h3>
<p>四、出问题能不能接受 30 分钟以上的中断？五、预算是否允许为固定地址多付两成？两个都「是」，选固定住宅出口；有任意一个「否」，先用可更换的住宅池跑一段，再决定是否升级。</p>

<h2>常见问答</h2>
<h3>静态 IP 和静态住宅 IP 是一回事吗？</h3>
<p>答：不是。静态说的是地址是否固定，住宅说的是归属类型。静态 IP 可能是机房段，静态住宅 IP 才是地址固定且归属为家庭宽带，采购时要同时确认这两点。</p>
<h3>先用便宜的动态住宅，稳定了再换固定，可以吗？</h3>
<p>答：可以，而且推荐。但换的时候要留过渡期，让旧出口保留一到两周，确认新环境无异常后再释放，避免中途两边都不可用。</p>
<h3>并发不高但账号很多，怎么配更省？</h3>
<p>答：按账号分组共用出口，每组 3 至 5 个，组内账号尽量同类。这样既控制了出口数量，也保留了组间的独立性，比一人一条便宜很多。</p>
<h3>预算只够一条线路，应该优先保什么？</h3>
<p>答：优先保可用率和地址稳定，其次才是速度。速度不够可以靠错峰和队列缓解，出口频繁掉线则没有替代方案。</p>
